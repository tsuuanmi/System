## Is the present plugin architecture sufficient?

**Short answer: yes for MVP-0; preserve the current seams.** PR #2 has seven functional/workspace packages plus a DSH bundle (the seven are `artifacts`, `work`, `agents`, `verifiers`, `effects`, `app`, `fakes`). The active profile declares **13 Cordis rows** including DSH infrastructure and an optional disabled `fakes` row. See [bundle config](https://github.com/tsuuanmi/System/blob/709942819e56c57452bf72c2db019c845fca1d74/packages/bundle/cordis.patch.yml) and [package map](https://github.com/tsuuanmi/System/blob/709942819e56c57452bf72c2db019c845fca1d74/packages/README.md). "13 rows" means **profile rows**, not 13 new System plugins or 13 enabled optional products.

**Conclusions:** the existing capability registry can host Worker, Verifier and Effect providers. There is **no evidence yet** for splitting `@system/work` into several new plugins, introducing a custom plugin manager, or replacing DSH. One file containing multiple providers is not a defect unless independent enable/disable/lifecycle becomes an actual requirement.

## Actual architectural gaps to test, not conjectural plugin shopping

1. **Research evidence scope.** [Research workflow](https://github.com/tsuuanmi/System/blob/709942819e56c57452bf72c2db019c845fca1d74/workflows/research.yaml) produces a `report` and `sources` artifact, but the configured `research.citation-check` [verifies `$steps.investigate.sources` only](https://github.com/tsuuanmi/System/blob/709942819e56c57452bf72c2db019c845fca1d74/workflows/research.yaml); its [README](https://github.com/tsuuanmi/System/blob/709942819e56c57452bf72c2db019c845fca1d74/packages/verifiers/README.md) explicitly states **claims are not checked against quotations**. A passing source/quote check is **not** a passing report-level claim-support check. Test a deliberately unsupported claim with valid `sources.json`: current outcome may pass its configured contract. Resolve this by adding a *configured*, exact-subject `research.claim-support`/evidence-bundle verifier, not a universal review loop. First document the acceptance scope; then pin report + sources + evidence IDs together.
2. **Storage and multi-CLI concurrency.** [`FileControl`](https://github.com/tsuuanmi/System/blob/709942819e56c57452bf72c2db019c845fca1d74/packages/work/src/control.ts) coordinates per-Work locking/cancellation using PID lock files while DSH domain storage caches records in each host process. A [pnpm SQLite patch](https://github.com/tsuuanmi/System/blob/709942819e56c57452bf72c2db019c845fca1d74/patches/README.md) adds `PRAGMA busy_timeout=5000` to address `database is locked` across concurrent CLI processes; the [regression test](https://github.com/tsuuanmi/System/blob/709942819e56c57452bf72c2db019c845fca1d74/tests/concurrency.test.ts) exercises parallel commands. Busy timeout controls lock waiting; **it is not proof of cross-process cache coherency, crash-safe leader election or atomic transitions across domains**. Benchmark/chaos-test two processes submitting, reading, cancelling and resuming **the same Work**, stale process locks and interrupted artifact/effect writes. Consider a single state owner or generation fencing **only if a reproducible correctness gap appears**.
3. **Plugin composability beyond boot.** The effective 13-row profile uses DSH config and `fakes` disabled. `ctx.capabilities` supports registration and deregistration, but there is **no in-flight enable/disable experiment yet**. Distinguish (a) install/available, (b) configured/loaded, (c) admitted for Work, and (d) in-flight drain. This is compatibility work, not an automatic demand for a second plugin host.
4. **Behavioral evaluation and observability.** 114 unit and 34 smoke tests plus real two-Worker/two-workflow proofs are reported in the pinned PR #2 snapshot; this does not determine success rates over diverse tasks, latency breakdown, operator decisions per accepted Work, provider-quota exhaustion, source-change sensitivity or regression on model upgrades. Prefer repeatable **behavioral fixtures and recorded evidence** before broad benchmark suites.
5. **Worker/runtime portability.** `@system/agents` already owns native CLI account/tier handling. Stock DSH subagent [request](https://github.com/deepseek-ai/deepseek-harness/blob/66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db/packages/subagent/subagent/src/types.ts) supports `cwd` but requires a parent DSH Agent; its public result does not include usage/worktree changes. Replacing the adapter with stock subagents would lose product-specific data without a wrapper/upstream change. Reassess only after a pinned API comparison.

## DSH official plugins: reuse versus adapter requirements

**Critical compatibility rule:** DSH's **service providers** are often reusable from another Cordis plugin. A `dsh-tool-*` plugin usually exposes tools to the **DSH agent loop**; System's Claude/Codex Workers are separate native agents. Mounting a DSH model-facing tool **does not automatically equip external Workers with that tool**. Test an explicit integration bridge (host service -> Artifact, or external CLI tool/MCP interface), and do not silently mount the DSH model loop to work around it.

## Research experiments and decision gates

| Experiment | Competing approaches | Measurable proof / decision |
|---|---|---|
| E1 Research verifier quality | current quote-presence; report/claim graph; independent model verifier | Create fixtures with valid URLs/quotes but unsupported report claims, swapped report, inaccessible sources and changed pages. Reject false `pass`, preserve `inconclusive`. |
| E2 Source Artifact capture | own HTTP fetch; `ctx.web` + `web-fetch-http` adapter | Verify byte/content identity, URL/redirect/metadata, source timing and failed fetch, complete provenance; note SSRF/egress limitations as a future scope. |
| E3 Multi-process storage | current SQLite busy-timeout + PID locks; single state owner; generation fence | Stress `submit/run/cancel/retry/show` across hosts plus SIGKILL. No lost update, double dispatch or false replay success. Collect latency and affected record sizes. |
| E4 Provider contract | existing 2 Worker adapters; DSH stock subagents; third fake provider | Execute the same Artifact contract without controller changes. Record differences in cwd, credentials, usage and output capture. |
| E5 Plugin toggling | config disabled before boot; disable while Work running | Prove no new work enters a disabled capability; drain/hold/reconcile existing Work; enabled plugin's dependencies are explicit. MVP-0 does **not** claim this test passed. |
| E6 Skills | native Claude/Codex skills; DSH skill provider; explicit pinned Skill Artifact | A prompt/workflow with vs without skill should show measurable benefit; no model loop duplication or ambient source drift. |
| E7 Quality/ops | existing `work report`; structured event export; behavioral eval runner | Track acceptance rate, false-pass rate, operator touches per accepted Work, time by phase, attempts, unknown usage and reproducible fixture regression. |
| E8 Dependency/patch | pinned DSH SQLite patch; upstream alternate version/provider | Confirm upstream fix and concurrent correctness before removing patch; maintain one exact pin and rollback test. |

## Decision guidance

**Near term:** strengthen correctness and evidence of the *existing* seams. The first expansion candidate is **research source/evidence verification**; the next infrastructural question is **multi-process Work ownership**; the first DSH service reuse experiment is **`ctx.web.fetch` -> immutable Artifact**.

**Do not** add a plugin merely because one exists in DSH/System 1. A candidate graduates when (1) a concrete use case fails without it, (2) it fits a current contract without hidden alternative state ownership, (3) its DSH version/dependency closure is pinned, (4) fake tests and a real fixture pass, and (5) the operator sees a measurable benefit.

Decisions and scheduling are proposed in [PROP-0002](../proposals/PROP-0002-post-mvp-roadmap.md). This research **does not reopen ADR-0001–0004** or claim that PR #2 has merged.
