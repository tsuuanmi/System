# @system/runtime-cli adapters

One adapter per CLI Runtime. Everything that differs between Runtimes lives here; `agent.ts`, `ask.ts` and `index.ts` ask the registry and never branch on a Runtime's name (`tests/adapters.test.ts` fails if one does).

- [types.ts](types.ts) — `CliAdapter`: invocation, credential staging (`preflight`), output parse, progress, attempt summary, quota reader, account identity, registration.
- [index.ts](index.ts) — the registry keyed by Runtime name (`adapterFor`) and `summarizeAttempt`.
- [claude-code.ts](claude-code.ts) — Claude Code, with the flags pinned by rb-4 (`--allowedTools`, `--disallowedTools`).
- [sandbox.ts](sandbox.ts) — the `sandbox` Account option (off by default, every CLI Runtime): the bubblewrap layer around the Runtime's process, as a pure function (argv in, argv out; the host's facts as arguments).
- [final-result.ts](final-result.ts) — shared `{status: done|blocked, reason}` final-result schema and parser for Codex and Antigravity (`finish-1`); `blocked` fails the attempt with the Worker's own reason (never "no change" or a missing output), a missing or invalid result fails naming it, and the structured `finalResult` is kept in `WorkerResult` and the `observed` attempt record.
- [codex.ts](codex.ts) — Codex, with `-s workspace-write`, `--output-schema <ws.root>/final-result.schema.json` and `-o <ws.root>/final-result.json`.
- [antigravity.ts](antigravity.ts) — Antigravity (`agy`): `-p <prompt> --output-format stream-json --model <m> --mode accept-edits --sandbox --add-dir <in> --add-dir <out> --json-schema <schema>`, run with `cwd` the checkout, `HOME` the attempt's throwaway home (agy 1.5.18's print mode has no `--gemini-dir`) whose `.gemini/antigravity-cli` is a real directory holding only symbolic links to the Account's `antigravity-oauth-token` and `settings.json`, and no session bus, so the login is read through that link by `agy`, never by System, while caches, tool stores and agy's working files (`brain/`) stay in the throwaway home (linking the whole `.gemini` made agy's own permission check refuse `brain/`, which resolved into `<agyHome>`). `<agyHome>/.config/antigravity/credential-user-scope` is not shared. `--mode auto` is refused for these Accounts, so `accept-edits`; never `--dangerously-skip-permissions`. `--sandbox` is left out when the Account's `sandbox` option puts the process in the bubblewrap layer (agy's sandbox hides the home, so `node` would be the system's v10, not the repository's); the scope then records `sandbox: 'bubblewrap'` instead of `true`. Headless permissions are file rules, not flags: staging writes `<agyHome>/.gemini/antigravity-cli/settings.json` (allow `command(*)`, deny `command(git push)` and `command(gh)`; the `:*` and `gh *` forms do not deny) before each attempt, the same bytes every time. An Account is one quota group (`quotaGroup`: `gemini` or `3p`), read from `agy -p /usage`; a reset of 1970 is an unknown reset. A quota or 429 error is worded so the attempt is recorded as limited. A result with `denied_actions` and an empty response (headless mode auto-denies what it would prompt for, such as a read outside the added directories) fails the attempt naming the actions; with a response it is only noted. agy 1.5.18 puts the structured result in the text of the last `agent_response` step (the `text_delta`s of that `step_index`) and a prose summary in `result.response`; the adapter reads the step first and falls back to `result.response` when that is JSON. No Classifier question runs on it.

**`sandbox` option.** An Account whose profile sets `sandbox: true` runs its Runtime's process (Claude Code, Codex or Antigravity) inside one bubblewrap layer, the same OS user, started by `agent.ts` ([ADR-0016](../../../../docs/decisions/ADR-0016-the-gate-is-enforced-by-reachability.md) decisions 2, 3, 6): the passwd home (not `$HOME`) and `$DSH_HOME/system` are hidden, the attempt's directory is bound read-write, the repository's git directory is bound read-write with its `config` and `hooks/` read-only over it (the worktree commits; it cannot plant a hook), and the toolchain under the home is bound read-only (each PATH entry and what its files need, the Runtime's binary by its real directory; never a PATH entry's parent as such); every link under the attempt home to an Account's state (Antigravity's `.gemini/antigravity-cli/...`) is bound read-write. What exactly is bound is stated once, in the comment at the top of [sandbox.ts](sandbox.ts). The network is kept. When `bwrap` is missing or cannot start, the attempt fails with cause `load` and the Runtime never runs; the attempt's `scope.sandbox` records the layer. Without the option the argv and environment are unchanged. `tests/sandbox.test.ts` runs a fake agent through it, nested too.

The `web` Runtime has no adapter: the runtime-web row serves it. Adding a CLI Runtime is writing one adapter and registering it. See the [package README](../../README.md).
